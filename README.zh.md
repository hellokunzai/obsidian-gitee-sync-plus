# Gitee Sync Plus

[English](./README.md)

Gitee Sync Plus 将 Obsidian vault 中的笔记以普通文件形式保存到私有 **Gitee 或 GitHub 仓库**。插件直接连接平台 API，无需服务器或本地安装 Git，并支持桌面端、iOS 和 Android。

## 功能特性

- **双向增量同步**：vault 与私有 Git 仓库之间的双向增量同步。
- **三方合并**：使用 Git blob 内容哈希，对本地 vault、远端仓库、以及每台设备上次成功同步的基线进行三方比较，跨设备正确处理删除与冲突。
- **冲突解决**：同一文件在两端都被修改时，可逐文件选择「保留本地 / 使用远端 / 合并区块」，并支持「全部应用到」。
- **Git 面板**：右侧栏的源控风格视图，展示「已暂存 / 未暂存 / 远端」变更，支持提交、拉取、丢弃、暂存/取消暂存、单文件差异查看。
- **差异查看器**：并排或合并视图对比本地与远端版本，可逐块回退修改，或将文件标记为已同步。
- **自动同步**：支持定时器、启动时、以及手动触发（侧边栏图标、状态栏、命令面板、Git 面板）。
- **同步预演**：把计划动作写入诊断笔记，不实际修改任何一端。
- **安全的令牌存储**：令牌存入 Obsidian 钥匙串（`data.json` 中不再保留明文），每个后端可管理多个命名令牌。
- **提交模式与合并策略**：支持「单文件提交 / 批量提交」，以及可配置的合并策略（`mtime` / `remote` / `local`）。
- **排除规则**：通过 vault 根目录的 `.gitignore` 文件定义。
- **双语界面**：自动跟随 Obsidian 语言，目前支持中文和英语。

## 工作原理

同步引擎为每个文件计算 Git blob 内容哈希，并对 **本地 vault、远端仓库、每台设备的基线**（上次成功同步的状态，保存在插件 localStorage 中，绝不写入 `data.json`，因此始终只属于本设备）进行 **三方比较**。

- 只在本地修改的文件会上传，只在远端修改的文件会下载。
- 删除会双向传播。
- 两端同时修改同一文件时，保留修改时间较新的版本（或由配置的合并策略决定）。
- 每次文件上传或删除都会生成仓库 commit，旧版本可随时通过 Git 历史恢复。
- 若远端平台返回被截断的文件树，会中止同步，避免误判为批量删除。

插件界面会自动跟随 Obsidian 的语言，目前支持中文和英语。

## 安装

在 Obsidian 中打开 **设置 → 第三方插件 → 浏览**，搜索 **Gitee Sync Plus**，安装并启用插件。

本地开发版本可手动构建安装：

```bash
npm install
npm run build

mkdir -p "<vault>/.obsidian/plugins/gitee-sync-plus"
cp main.js manifest.json "<vault>/.obsidian/plugins/gitee-sync-plus/"
```

## 仓库和令牌

**Gitee：** 创建私有仓库，然后在 **设置 → 安全设置 → 私人令牌** 中创建令牌，并勾选 **projects** 权限。

**GitHub：** 创建私有仓库。Fine-grained token 需要目标仓库的 **Contents: Read and write** 权限；classic token 需要勾选 `repo`。

在支持钥匙串的环境下，令牌会存入 Obsidian 钥匙串（设置 → 钥匙串），不再写入 `data.json`。每个后端可管理多个命名令牌，在设置面板中切换使用。

## 配置

| 设置项 | 说明 |
|---|---|
| 存储后端 | Gitee 仓库或 GitHub 仓库 |
| 用户名 | 仓库 URL 中的用户或组织名 |
| 仓库名 | 用于保存 vault 的私有仓库 |
| 分支 | Gitee 默认 `master`，GitHub 默认 `main`。填写用户名/仓库名/令牌后，下拉框会自动从接口拉取分支 |
| 令牌 | 已保存的私人访问令牌，存入 Obsidian 钥匙串。点击「选择秘钥」添加或选择（支持搜索与删除），点击「测试」验证是否可用 |
| 自动同步间隔 | 同步间隔分钟数，`0` 表示关闭 |
| 启动时同步 | Obsidian 打开后执行一次同步 |
| 提交模式 | **单文件独立提交**（默认）或 **全部变更合并为一次提交（批量）** |
| 合并策略 | 自动同步/启动同步/定时同步时如何解决同文件冲突：**保留最新修改时间**（较新者胜）、**全部使用远端**、**全部保留本地** |
| 同步按钮 | 开启后在左侧栏显示同步按钮 |
| Git 面板按钮 | 开启后在左侧栏显示 Git 面板按钮 |
| 调试日志 | 将同步计划和结果写入 `_gitee-sync-plus-log.md` |
| 排除目录 | vault 根目录 `.gitignore` 原始规则，下次同步时生效 |

可通过侧边栏同步图标、命令面板中的 **立即同步**、状态栏、定时器、启动时同步或 Git 面板触发。使用 **预览同步计划** 可以在不修改两端文件的情况下检查计划动作。

## Git 面板

Git 面板是右侧栏的源控风格视图，模仿常见 IDE 的源代码管理侧栏，但运行在插件的三方同步模型之上（无需本地 Git 二进制）。可通过命令 **打开 Git 面板** 或可选侧边栏按钮打开。

- **已暂存 / 变更 / 远端** 三个分组列出下次同步会涉及的所有文件。
- **提交（Commit）** 推送已暂存的本地变更（可填写提交说明；批量模式下说明作用于整个提交）。
- **拉取（Pull）** 下载远端变更；若存在冲突，会先弹出冲突解决弹窗。
- **丢弃（Discard）** 将本地改动回退到上次同步的远端版本（纯本地新增文件则删除）。
- **查看差异** 打开差异查看器查看任意变更文件。
- 面板会在 vault 变更时（防抖）自动刷新，并显示当前的 `用户名/仓库@分支` 目标。

## 冲突解决

当某个文件自上次同步以来在 **两端都被修改** 时，即产生冲突。

- 通过 Git 面板 **拉取** 时，会弹出弹窗列出全部冲突。对每个文件可选择 **保留本地**、**使用远端**，或打开 **合并** 编辑器逐块选择（保留本地 / 保留远端 / 两者都保留）并保存合并结果；**全部使用远端 / 全部保留本地** 可一次性解决所有冲突，随后 **确认拉取** 应用选择。
- 在 **自动同步 / 启动同步 / 定时同步**（无交互提示）时，由配置的 **合并策略** 决定：`mtime` 保留较新版本，`remote` 始终取远端，`local` 始终保留本地。

差异查看器也可用于对比版本、逐块回退修改，或将文件标记为已同步。

## 命令

| 命令 ID | 名称 | 说明 |
|---|---|---|
| `sync-now` | 立即同步 | 执行一次完整双向同步 |
| `sync-preview` | 预览同步计划 | 计算计划并写入诊断笔记，不实际改动 |
| `open-git-panel` | 打开 Git 面板 | 打开右侧栏 Git 面板 |

## 多设备

在每台设备安装插件并配置同一仓库。每台设备分别保存同步基线。新设备首次同步会下载远端 vault，之后只进行增量同步。

移动端进入后台后，系统可能暂停定时器，建议开启 **启动时同步**。

## iOS 文件显示

如果同步后能看到新目录，却看不到某些非标准扩展名文件，请打开 **设置 → 文件与链接 → 检测所有文件扩展名**。文件可能已经下载，只是被 Obsidian 文件列表隐藏。

## 同步规则

- 只在本地修改的文件会上传，只在远端修改的文件会下载。
- 删除会双向传播。本地删除进入 Obsidian 回收站，远端文件仍可通过 Git 历史恢复。
- 两端同时修改同一文件时，保留修改时间较新的版本；修改优先于删除。
- `.obsidian`、`.git` 等隐藏路径在两端都会被忽略。
- 远端平台返回被截断的文件树时会中止同步，避免误判为批量删除。
- 每次文件上传或删除都会生成仓库 commit，旧版本可随时恢复。

## 限制与安全

- 大型 vault 首次同步在单文件模式下会逐文件生成 commit，可能受到平台 API 限流影响。
- 建议将大附件放入排除目录，单文件尽量保持在 50 MB 以下。
- 令牌存入 Obsidian 钥匙串（设置 → 钥匙串），不再保存在 `data.json` 中。使用其他工具备份 vault 时无需特别排除令牌。在移动端或较旧、不支持钥匙串的 Obsidian 版本中，令牌会回退存储到 `data.json`。
- 插件管理仓库后，不要同时把同一个 vault 手动推送到相同仓库。
