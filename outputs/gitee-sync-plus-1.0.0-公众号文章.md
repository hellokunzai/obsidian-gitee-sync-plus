# 🔔 开篇导语

事情要从一款叫「墨光批注」的插件说起。

最近在 Obsidian 里读 epub 电子书，发现了这款批注插件——划重点、做笔记、记录阅读进度，体验相当不错。但它有一个让我头疼的问题：所有的批注数据和阅读进度都存储在 `.obsidian-annotations` 这个隐藏目录下。

为什么「隐藏目录」是个问题？因为我用的同步插件叫 **Gitee Sync**，它会硬编码跳过所有以 `.` 开头的文件和文件夹。也就是说，我在电脑上辛辛苦苦标注的内容，到了手机上打开——空白，什么都没有。

这就引出了故事的起点：为了解决这个小问题，我最终 fork 了一个项目，改写了同步引擎，发布了一个全新的插件——**Gitee Sync Plus**。

# 为什么是 Gitee Sync

先说一个前提：市面上的 Obsidian 同步方案其实不少。

官方 Obsidian Sync 好用但收费，iCloud / OneDrive 在 Windows 和 Android 之间经常抽风，纯 Git 方案需要每台设备都装 git 程序——手机端基本没戏。社区插件里，Remotely Save 功能强大但配置复杂，Self-hosted LiveSync 需要自己搭服务器。

Gitee Sync 是我找到的**唯一一款同时满足这三个条件**的插件：

- **操作简单**：填好 Token、用户名、仓库名就能用，没有多余的概念
- **双平台支持**：Gitee 和 GitHub 都行，国内用户用 Gitee 速度飞快
- **不依赖 git 程序**：PC 端和移动端都不需要装 git，插件自己通过 API 完成所有操作

这三个条件卡下来，市面上就剩 Gitee Sync 一根独苗。

但它有一个致命缺陷：**硬编码过滤规则**。所有以 `.` 开头的隐藏文件一律跳过，用户没法改，也没地方配。

# 一个看似很小的改动

我的需求其实很简单：让 `.obsidian-annotations` 能被同步。

逻辑上这应该就是改一行代码的事——把硬编码的隐藏文件过滤去掉，或者加个白名单。但当我真正开始看源码的时候，发现事情没那么简单。

原插件的过滤逻辑散落在同步引擎的各个角落：`excludedPrefixes()` 硬编码了一个前缀列表、文件遍历用的是 `vault.getFiles()`（Obsidian 的索引 API，天然不返回隐藏文件）、排除判断直接写死了逻辑。如果你只改一个地方，其他地方的逻辑会继续拦截，最终结果是改了也白改。

这时候我意识到：与其在硬编码规则上打补丁，不如**彻底重构过滤机制**，让所有排除规则统一走 `.gitignore` 文件。

这个思路本身并不复杂——Git 生态里 `.gitignore` 是标配，规则语法大家都会写，而且 Obsidian 用户大概率已经在仓库里有一份了。改完后，用户想排除什么就在 `.gitignore` 里加一行，想同步隐藏目录就把对应规则删掉，控制权完全在自己手里。

# 当改动越滚越大

实现这个思路，我动了这些地方：

**新增 `src/gitignore.ts`（154 行）**：用 `ignore` npm 包做标准 `.gitignore` 规则匹配，自动创建默认文件、管理插件专属的排除规则块。

**重写文件操作层**：把所有文件读写从 `vault.getFiles()` / `vault.readBinary()` 改为 `vault.adapter` 的原生方法。前者只能操作 Obsidian 索引里的文件（隐藏文件不在索引内），后者直接操作磁盘文件。

**旧配置迁移**：老用户的 `excludeFolders` 设置自动写入 `.gitignore`，迁移完清空旧字段，不留历史包袱。

改到这里，我发现事情已经变味了——这不再是对原插件的「修修补补」，而是对同步引擎核心逻辑的彻底重写。我的设计理念（用户通过 `.gitignore` 完全控制过滤规则，而不是插件替你决定）已经和原插件（硬编码规则、隐藏文件一律跳过）**背道而驰**。

继续往原仓库里塞代码只会把两个方向搅在一起。于是我决定：**新开一个项目，从原代码 fork 出来，独立发展。**

这就是 Gitee Sync Plus 的来历。

# 顺便把其他槽点也修了

既然重开了项目，干脆把原插件几个长期存在的体验问题一并解决：

**分支选择从文本框改成动态下拉框。** 老版本让你手动敲 `main` 或 `master`，拼错了同步就失败。现在填好仓库信息后点一下刷新，自动从 API 拉取分支列表，下拉选择就行。有 5 分钟缓存，不会频繁调接口。

**Gitee 和 GitHub 的设置项顺序统一。** 之前两个平台的配置项排列不一致，Token 的位置都不一样，切换平台时容易懵。现在统一成 Token → 用户名 → 仓库名 → 分支。

**插件改名为 Gitee Sync Plus。** 社区市场里已经有同名的 `gitee-sync`，为了避免混淆，ID 改为 `gitee-sync-plus`。

改动总计 13 个文件，523 行新增，125 行删除，版本号重置为 1.0.0。

# 🚀 如何安装使用

**新用户：**

1. Obsidian → 设置 → 第三方插件 → 关闭安全模式
2. 点击「浏览」，搜索 **Gitee Sync Plus**
3. 安装后配置 Gitee / GitHub 的 Token、用户名、仓库名、分支
4. 插件自动在 vault 根目录生成 `.gitignore`，按需调整排除规则

**从旧版 Gitee Sync 迁移：**

1. 1. \`卸载旧插件
2. 安装 Gitee Sync Plus
3. **重新配置** Token 和仓库信息（数据不自动迁移）
4. 旧的 `excludeFolders` 设置会自动写入 `.gitignore`
5. 手动同步一次，确认 `.obsidian-annotations` 之类的隐藏目录已经在同步范围内

## 常见问题

**Q：我之前的同步状态会丢吗？**

A：会，这是 breaking change。本地状态 key 改了，旧基线不兼容。执行一次完整同步即可重建。

**Q：我手写的 .gitignore 规则会被插件覆盖吗？**

A：不会。插件只管理 `>>> gitee-sync-plus managed exclusions >>>` 注释块内的规则，块外的规则完全不受影响。

**Q：GitHub 能用吗？**

A：能。Gitee 和 GitHub 双平台都完整支持，在设置里切一下就行。

# 📋 写在最后

Gitee Sync Plus 算不上什么宏大的项目，说白了就是一个「折腾出来的副产品」。起因只是想让自己在不同设备上读电子书的批注能同步过去，结果一路改下来，发现原来的思路已经走不通了，索性新起炉灶。

但这个过程中有个体会挺深的：**好的工具应该把控制权交给用户。** 一个插件不该替用户决定哪些文件该同步、哪些不该——这件事应该由用户自己通过 `.gitignore` 来控制，清晰、透明、可预期。

如果你也在用 Gitee 或 GitHub 同步 Obsidian 笔记，而且曾被硬编码的过滤规则困扰过，不妨试试 Gitee Sync Plus。一个 `.gitignore` 文件，解决所有烦恼。
