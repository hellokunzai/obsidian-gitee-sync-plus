# Gitee Sync Plus · 界面美化优化方案

> 状态：方案 + HTML 原型阶段，待确认后进入开发（按 obsidian-plugin-dev 阶段一协议，本节点需用户确认）。
> 范围：仅前端视觉/交互层（Settings / Git 侧边栏 / Diff 视图 / Token 弹窗），不改动同步引擎逻辑。

---

## 一、现状分析

| 维度 | 现状 | 评价 |
|---|---|---|
| 主题适配 | `styles.css` 已全面使用 Obsidian CSS 变量（`--background-*`、`--text-*`、`--color-*-rgb`），亮/暗自动跟随 | ✅ 良好，是后续美化的基础 |
| 视觉层次 | 侧边栏/设置以扁平行 + 细线分隔为主，分组标题仅是加粗文字 | ⚠️ 层次偏平，信息密度高时不易扫读 |
| 状态可视化 | 文件状态用单字母标签 `M/U/D/↓` + 颜色，缺少图例与汇总 | ⚠️ 新用户需猜含义 |
| 卡片化 | 列表项、Token 项均为裸行，无边框/圆角/悬浮反馈 | ⚠️ 偏“工程感”，缺少精致度 |
| 微交互 | 已有 hover 显隐、collapse，但无焦点环、无动效节奏 | ⚠️ 可增强“被响应”的反馈感 |
| 空状态 | 分组空时用“无”占位，较朴素 | ⚠️ 可加入引导性空状态 |

**结论**：底层规范正确，主要差距在「信息层次、状态可视化、卡片化与微交互」。美化目标是在 Obsidian 原生设计语言内做**精致化升级**，而非另起炉灶。

---

## 二、设计方向

**Refined Source-Control（精致化源代码管理风）**

- 在 Obsidian 现有组件语言内升级，不引入突兀的第三方视觉。
- 强调色采用克制的「靛蓝」`--accent`，呼应“云同步/连接”语义；状态色沿用 Obsidian 的 green/amber/red/blue。
- 四层视觉锚点：**分组标题（eyebrow）→ 卡片行（card）→ 状态点（dot）→ 悬浮动作（hover-reveal）**。
- 动效克制：仅 hover、active、焦点、分组展开做过渡，尊重 `prefers-reduced-motion`。

## 三、各界面优化点（对照表）

### 1. 设置面板 `settings.ts` + `styles.css`
| 元素 | 现状 | 优化 |
|---|---|---|
| 分组标题 | 仅加粗文字 `.section-header` | 改为 **eyebrow 风格**：左侧小图标 + 大写 letter-spacing 标签 + 向右延伸的发丝分隔线；在滚动区 sticky |
| 后端选择 | 下拉框 `gitee/github` | 升级为**分段控件（segmented pill）**，图标 + 文案，选中态填充强调色 |
| Token 行 | “选择令牌” + “测试”两个纯按钮 | 增加**连接状态芯片**：当前令牌名 + 状态点（绿=已连通 / 灰=未选 / 红=失败），“测试”结果以 chip 反馈 |
| 输入框/文本域 | 默认 Obsidian 控件 | 增加 focus 焦点环（`--text-accent`）、内边距与圆角微调；`.gitignore` 编辑器加标题条“排除路径 (.gitignore)” |
| 整体节奏 | — | 引入 design tokens（`--gsp-radius / --gsp-gap / --gsp-shadow`），统一间距与阴影 |

### 2. Git 侧边栏 `GitPanelView.ts` + `styles.css`
| 元素 | 现状 | 优化 |
|---|---|---|
| 头部 | 标题 + 状态文字 + 仓库信息文字 | 增加**连接状态胶囊**（点 + “已同步 / N 处更改 / 同步中…”）；仓库信息收为**仓库芯片**（图标 + owner/repo@branch） |
| 提交框 | 纯 textarea | 内嵌式卡片：等宽字体、占位提示、右侧字数/模式提示 |
| 操作按钮 | 三个等权按钮 | **Commit 为主按钮（填充强调色）** + Pull/Refresh 为幽灵按钮，均带图标；悬浮微抬升 |
| 分组标题 | 文字 + 计数 + 折叠箭头 | 图标 + **计数胶囊（pill）**；整体可点折叠，hover 高亮 |
| 文件行 | 字母标签 + 路径 + hover 动作 | **卡片行**：左侧彩色状态点 + 路径 + 右侧悬浮显隐的 查看/丢弃/暂存 动作；状态点配图例 |
| 暂存开关 | `+ / -` 文本按钮 | 改为**小型圆形勾选/取消**控件，语义更清晰 |
| 空状态 | “无” | 居中图标 + 引导文案 + 操作（“全部已同步 ✓” / “暂无本地更改”） |

### 3. Diff 视图 `DiffView.ts` + `styles.css`
| 元素 | 现状 | 优化 |
|---|---|---|
| 头部 | 路径 + 布局/折叠按钮 | 路径前加**文件类型图标** + **变更类型徽章**（修改/新增/删除/远端）；按钮行精致化 |
| 双栏 | 栏目标签 + 行号 + 行内容 | 栏目标签 **sticky**；行号列 refined；变更行加**左侧强调竖条**；chunk 还原按钮 hover 才显强调色 |
| 相同内容提示 | 居中文字 | 居中插画式图标 + 双操作按钮，信息更友好 |
| 滚动同步 | 仅边框提示 | 滚动时栏目标签加轻微高亮，强化“联动”感知 |

### 4. Token 弹窗 `token-manager.ts` + `styles.css`
| 元素 | 现状 | 优化 |
|---|---|---|
| 搜索框 | 纯 input | 带搜索图标的输入框，focus 焦点环 |
| 列表项 | 行 + 单选 + 眼睛 + 删除 | **可选卡片**：单选点 + 名称 + 选中徽章 + hover 抬升；眼睛展开令牌值（等宽）；删除确认 |
| 新增表单 | 两输入框 + 按钮 | 收为**卡片表单**，确认/取消对齐 |
| 页脚 | 新增 + 保存/取消 | 主按钮 Save（填充）+ Cancel（幽灵），右对齐 |
| 空状态 | “无令牌” | 居中图标 + 引导“点击新增你的第一个令牌” |

## 四、跨切面改进

- **Design tokens 层**：在 `styles.css` 顶部集中定义 `--gsp-*` 变量（间距/圆角/阴影/强调软色），全部引用 Obsidian 原生变量派生，便于统一调校。
- **微交互**：hover 抬升、active 按压、`:focus-visible` 焦点环、`collapse` 高度/透明度过渡；统一 `transition` 节奏（0.12–0.18s ease）。
- **无障碍**：保留并补全 `aria-label`；键盘可达；新增可见焦点样式；状态色不只靠颜色（点 + 文字/图标双重编码）。
- **性能**：仅 CSS 过渡 + 既有 DOM；不引入新依赖、不做重排密集动画。
- **主题**：全部颜色走 Obsidian 变量，亮/暗天然适配；原型内置双主题切换验证。

## 六、风险与约束

- ⚠️ **不可破坏现有 class**：TS 中大量按 class 选择器取 DOM（如 `gitee-sync-plus-panel-list`、`gitee-sync-plus-token-item`），美化只增不改名。
- ⚠️ **i18n 强制**：任何新增用户可见文案必须走 `t()`，至少 `en` + `zh-cn` 两套（见 obsidian-plugin-dev 四大铁律）。
- ⚠️ **不硬编码颜色**：全部使用 Obsidian CSS 变量 / `rgba(var(--color-*-rgb), …)`，保证亮暗主题一致。
- ⚠️ **保持 `isDesktopOnly: false`**：不引入 Node 专属 API；移动端 UI 仍可用。
- ✅ 构建须通过 `npm run build`（tsc 类型检查 + esbuild）。
