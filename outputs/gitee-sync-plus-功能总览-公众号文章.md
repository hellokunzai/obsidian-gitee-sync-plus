# Gitee Sync Plus 全功能详解：从修一个同步痛点，到给 Obsidian 装上 IDE 级版本控制

## 🔔 开篇导语

事情要从一款叫「墨光批注」的插件说起。

最近在 Obsidian 里读 epub 电子书，发现了这款批注插件——划重点、做笔记、记录阅读进度，体验相当不错。但它有个让我头疼的问题：所有批注数据和阅读进度都存在 `.obsidian-annotations` 这个隐藏目录下。

而我当时用的同步插件会**硬编码跳过所有以 `.` 开头的文件**。于是我在电脑上辛辛苦苦标的注，手机上打开——空白，什么都没有。

为了修这个小问题，我 fork 了一个项目，改写了同步引擎，发布了一个全新插件——**Gitee Sync Plus**。这之后的几轮迭代里，它又从「能同步隐藏文件的工具」一路长成了「Obsidian 里的 IDE 级版本控制面板」。

这篇文章把来龙去脉和**到现在为止的全部功能**一次性讲清楚。

## 一、它到底解决什么？先聊聊同步方案的现状

Obsidian 多设备同步，市面上的方案其实不少，但各有硬伤：

- **官方 Obsidian Sync**：好用但收费，长期是一笔持续开销。
- **iCloud / OneDrive**：Windows 和 Android 之间经常抽风，冲突文件满天飞。
- **纯 Git 方案**：免费、可控，但每台设备都得装 git 程序——**手机端基本没戏**。
- **Remotely Save / Self-hosted LiveSync**：功能强，但配置复杂，后者还得自己搭服务器。

Gitee Sync Plus 想做**同时满足三件事**的那一个：

- **操作简单**：填好 Token、用户名、仓库名就能用，没有多余概念。
- **双平台**：Gitee 和 GitHub 都行，国内用户用 Gitee 速度飞快。
- **不依赖 git 程序**：PC 和手机都不用装 git，插件自己通过平台 API 完成所有操作。

它把 vault 以**普通文件**形式存进你的私有 Gitee / GitHub 仓库，桌面端、iOS、Android 通吃。

## 二、核心：同步引擎（1.0.0 重写的底座）

### 1. 用 .gitignore 替代硬编码过滤

原插件硬编码跳过点号开头的隐藏文件，用户改不了、配不了。我做的第一个大改动，是把所有排除逻辑统一收拢到 vault 根目录的 **`.gitignore`** 文件里。

- 新增 `gitignore.ts`，用 `ignore` 这个 npm 包做标准 `.gitignore` 规则匹配。
- vault 根目录没有 `.gitignore` 时，自动创建默认文件，预置 `.git`、`.trash`、日志文件、`.obsidian/workspace.json` 等常见排除项。
- 插件只管理一段带特殊注释的「管理块」（`>>> gitee-sync-plus managed exclusions >>>` … `<<<` …），**块外你手写的规则完全不受影响**。
- 老用户的旧 `excludeFolders` 设置会自动迁移进 `.gitignore`，迁移完清空旧字段，不留历史包袱。

结果就是：想排除什么，在 `.gitignore` 里加一行；想同步隐藏目录，把对应规则删掉——**控制权 100% 在你自己手里**。

> 📷 **配图建议**：横图，改造前后架构对比——左边硬编码过滤的散乱逻辑，右边统一走 .gitignore 的清晰结构

### 2. 三方对比 + 增量同步

同步引擎用的是 Git blob 内容哈希，对**本地 vault、远端仓库、每台设备上次成功同步的基线**做三方比较：

- 只在本地改的文件 → 上传；只在远端改的 → 下载。
- **删除双向传播**：本地删除进 Obsidian 回收站，远端文件仍可通过 Git 历史找回。
- 两端同时改同一文件 → **修改时间较新的赢**，修改优先于删除。
- 首次同步大 vault 会逐文件生成 commit，之后只做增量，旧版本随时可恢复。

### 3. 不踩坑的安全设计

- 远端平台返回**被截断的文件树**时会中止同步，避免被误判成「批量删除」把文件全干掉。
- 每次上传/删除都生成仓库 commit，等于自带版本历史。
- 提供**同步预演（Preview sync plan）**：不改任何一边，先把计划动作列给你看。

### 4. 多设备、多触发、多语言

- **多设备**：每台设备安装并配同一仓库，各自保存基线；新设备首次同步下载远端，之后增量。
- **触发方式**：侧边栏图标、命令面板「立即同步」、状态栏、定时器和启动同步，五选多。
- **自动同步间隔**：分钟数可调，`0` 表示关闭；还有「启动时同步」开关。
- **界面双语**：自动跟随 Obsidian 语言，中英文都支持。
- **iOS 文件可见性**：非标准扩展名文件同步后若看不见，去「设置 → 文件与链接 → 检测所有文件扩展名」打开即可（文件其实已下载，只是被列表隐藏）。

## 三、把同步工具升级成「版本控制面板」（1.0.2 主线）

1.0.0 解决了「能不能同步隐藏文件」，但同步体验还停留在「一键全量推送」。这轮我补上了 Git 用户最在意的三个能力：**看清要同步什么、看清改了什么、只提交想提交的**。

### 1. 侧边栏 Git 面板（仿 IDE 源控制栏）

新增一个独立侧边栏视图，长得像 VS Code 的源代码管理栏：

- 顶部显示当前仓库和分支（`gitee: 用户名/仓库@master` 或 `github: …@main`）。
- 一个提交信息输入框，支持 `Ctrl/Cmd + Enter` 直接提交。
- 三个按钮：**提交 / 拉取 / 刷新**。
- 改动分成三组：**暂存区（Staged）** / **更改（Changes）** / **远端更改（Remote）**，每组带计数。
- 文件列表每行显示状态标签（`M` 修改 / `A` 新增 / `D` 删除）+ 路径。
- **自动刷新**：编辑器里改了、新建了、删了、重命名了任何文件，面板 1.5 秒后自动重新计算（去抖，不狂刷接口）。

> 📷 **配图建议**：方图，Git 面板完整界面，红框标出三组与提交框

### 2. 差异对比视图（DiffView）

点文件列表里的「查看」图标，打开行级差异对比（这一块新建了 800+ 行）：

- **布局切换**：单栏内联 diff 与双文件完整视图之间切换。
- **收起未更改片段**：长文件只改几行时，中间没动的部分自动折叠成省略号，一眼定位改动。
- **同步滚动**：默认开启，两边对照滚动。
- **差异块一键还原**：每个改动区块旁有还原按钮，点一下恢复成「上次成功同步时的版本」。新增文件还原即删、删除文件还原即找回、修改文件还原即回退——**按块（hunk）回退，不是整文件**。
- 覆盖五种场景：本地新增 / 本地删除 / 本地修改 / 远端修改 / 远端删除，各有配色（删红 / 增绿 / 改橙）和还原逻辑。

> 📷 **配图建议**：横图，DiffView 单栏与双文件两种布局并排，圈出「还原块按钮」和「收起未更改」

### 3. 暂存区与选择性提交

这是从「全量推送」进化到「版本控制」的关键：

- 文件每行右侧有 `+` / `−` 图标，点 `+` 暂存、点 `−` 取消暂存；组标题上还有「全部暂存 / 全部取消 / 全部放弃」快捷按钮。
- 提交时**只推你暂存的文件**；一个都没暂存就点提交，会提示「没有可提交的文件」，不会稀里糊涂把乱改的一起推上去。
- 「放弃更改」做成带确认弹窗的危险操作，把本地文件恢复到上次同步的远端版本，避免手滑。

工作流就变成了 Git 用户最熟悉的那套：**看状态 → 看 diff → 挑文件暂存 → 写提交信息 → 提交。**

## 四、顺手做好的配置与体验

- **侧边栏按钮可配置隐藏**：固定在侧边栏的「同步图标」和「Git 面板图标」，在设置里能单独开关，嫌挤就只留一个；切换即时生效，不用重启。
- **设置面板重新分组**：按「账户 / 同步 / 排除 / 界面」归类，找东西不用从头扫到尾。
- **分支选择从文本框变成动态下拉框**：填好仓库信息后点刷新，自动从 API 拉分支列表，下拉选就行；有 5 分钟缓存，不频繁调接口。Gitee 和 GitHub 的设置项顺序也统一成 Token → 用户名 → 仓库名 → 分支。
- **插件改名 Gitee Sync Plus**：社区市场已有同名 `gitee-sync`，为避免混淆，ID 改为 `gitee-sync-plus`。

## 五、1.0.2：移动端兼容与合规

功能做完发版前，做了一轮合规审计，修的全是「桌面没事、移动端会崩」的坑：

1. **SHA-1 改用纯 JS 实现。** 原来用浏览器 `crypto.subtle.digest`，在移动端 webview 非安全上下文里可能为 `undefined`，同步一算哈希就崩。插件 `isDesktopOnly: false`，必须保证移动端可用。新增自包含纯 JS `sha1()`，严格按 Git blob 格式（`blob <size>\0<content>`）计算，用 `git hash-object` 端到端校验过：空文件、含中文 emoji、1MB 大文件，结果和 Git 完全一致。
2. **DiffView 不再依赖未公开 API。** 之前靠 `app.plugins.getPlugin()` 拿实例（不稳定），改成 `main.ts` 在 `onload()` 里用 `setDiffPluginInstance()` 主动注入单例，保留回退路径，更稳。
3. **设置面板类型收敛。** 分支下拉框组件类型、`selectEl` 清空方式都改成 Obsidian 官方推荐写法。
4. **版本映射对齐。** `versions.json` 补齐 1.0.1 / 1.0.2 映射（指向 `minAppVersion 1.8.7`），保证 BRAT 和社区市场正确路由；README 里「排除目录」说明从错误的「逗号分隔前缀」更正为「直接编辑 `.gitignore` 原始规则」。
5. **CI 自动构建。** 加了 GitHub Actions release 工作流：打 tag 并推送 → 自动 `npm install` + 构建出 `main.js` → 自动发 Release。以后发版只需打 tag，不用本地手工构建。

## 🚀 如何安装 / 更新

**新用户：**

1. Obsidian → 设置 → 第三方插件 → 关闭安全模式
2. 浏览，搜索 **Gitee Sync Plus**，安装启用
3. 配置 Gitee / GitHub 的 Token、用户名、仓库名、分支
4. 插件自动在 vault 根目录生成 `.gitignore`，按需调整排除规则
5. 左侧打开 Git 面板，体验一眼看全改动 + 选择性提交

**从旧版 Gitee Sync 迁移：**

1. 卸载旧插件，安装 Gitee Sync Plus
2. **重新配置** Token 和仓库信息（数据不自动迁移，这是 breaking change）
3. 旧的 `excludeFolders` 会自动写入 `.gitignore`
4. 手动同步一次，确认 `.obsidian-annotations` 之类的隐藏目录已在同步范围内

**已在用 1.0.0 / 1.0.1 的用户：** 通过 BRAT 或社区市场更新即可；**移动端用户这次必更**——之前版本在手机上同步可能因哈希崩溃。

## 常见问题

**Q：暂存区和 Git 的暂存区是一回事吗？**

A：概念一样——都是「标记哪些改动进入下一次提交」。但插件底层没有本地 git 程序，是基于自己的三方同步模型（本地 / 远端 / 上次同步基线）实现的，对 Obsidian 用户完全透明，不需要懂 Git。

**Q：放弃更改会丢文件吗？**

A：放弃的是「本地未同步的改动」，文件恢复到上次成功同步时的远端版本。操作前有确认弹窗，不会静默执行。

**Q：我手写的 .gitignore 规则会被覆盖吗？**

A：不会。插件只管 `>>> gitee-sync-plus managed exclusions >>>` 注释块内的规则，块外完全不受影响。

**Q：手机上能用 Git 面板吗？**

A：能。1.0.2 专门修了移动端哈希崩溃，iOS / Android 均可用，界面与桌面端一致。

**Q：会和 Obsidian 自带 Git 插件冲突吗？**

A：不会互相依赖，但建议别让两个工具同时管理同一个仓库，避免状态打架。

**Q：GitHub 能用吗？**

A：能。Gitee 和 GitHub 双平台完整支持，设置里切一下就行。

## 📋 写在最后

Gitee Sync Plus 算不上宏大项目，说白了是「折腾出来的副产品」——起因只是想让读电子书的批注能跨设备同步，结果一路改成了现在的样子。

但有两个体会挺深：

**第一，好的工具要把控制权交给用户。** 一个插件不该替你决定哪些文件该同步——这件事应该由你通过 `.gitignore` 来控制，清晰、透明、可预期。

**第二，同步不该是个黑盒。** 你有权在改动被推上去之前，看清它是什么、决定哪些要、哪些不要。Git 用几十年证明了这套心智模型是对的，那 Obsidian 里也该有。

如果你也在用 Gitee / GitHub 同步 Obsidian 笔记，欢迎试试。一个 `.gitignore` 文件 + 一个侧边栏面板，解决所有烦恼。
