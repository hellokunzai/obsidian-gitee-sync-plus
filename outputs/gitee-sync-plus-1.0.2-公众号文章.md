# 给 Obsidian 装上「IDE 级」Git 版本控制：Gitee Sync Plus 1.0.2 来了

## 🔔 开篇导语

上篇写了 Gitee Sync Plus 的诞生：因为原插件硬编码跳过所有隐藏文件，我 fork 出来重写了过滤机制，用 `.gitignore` 把同步的决定权交还给用户，发布了 1.0.0。

那一篇解决的是「能不能同步」的问题——特别是 `.obsidian` 下的隐藏配置能不能跟着走。

但 1.0.0 用下来，我发现它还有个没解决的本质问题：**它仍然是个「一键全量推送」的同步工具，而不是一个「版本控制面板」。**

什么意思？你永远不知道下一次同步会动哪些文件、每个文件到底改了什么、能不能只提交其中几个。这些恰恰是 Git 最核心、也最让人安心的三件事。

所以这轮更新，我给插件里里外外塞进了一套「仿 IDE 源控制栏」的体验。下面一个个说。

## 一、痛点：同步工具的三个盲区

先说清楚我到底在补什么。原来的同步流程是：点一下「立即同步」→ 插件算了份计划 → 一次性把所有改动推上去。

它在三个地方让我心里没底：

1. **看不到要同步什么。** 改了 20 个文件，你只知道「有改动」，但具体是哪些、本地还是远端，全靠猜。
2. **看不到改了什么。** 某个笔记被同步覆盖之前，你根本没机会看一眼它和远端的差别。
3. **不能选择性提交。** 本地手滑改乱了一个文件，你没法只提交另外 19 个干净的，只能要么全推、要么全不推。

Git 用户看到这里大概会笑：这不就是 `git status` / `git diff` / `git add -p` 天天干的事吗？

对，所以这轮更新的核心目标就一句话：**把这三个能力，照搬进 Obsidian 侧边栏。**

---

## 二、核心一：侧边栏 Git 面板（仿 IDE 源控制栏）

新增了一个独立的侧边栏视图，长这样——

- 顶部显示当前目标仓库和分支（`gitee: 用户名/仓库@master` 或 `github: ...@main`）
- 一个提交信息输入框（支持 `Ctrl/Cmd + Enter` 直接提交）
- 三个操作按钮：**提交 / 拉取 / 刷新**
- 下方把改动分成三组：
  - **暂存区（Staged）**：你已经决定要提交的文件
  - **更改（Changes）**：本地新增 / 修改 / 删除，还没暂存的
  - **远端更改（Remote）**：远端改了或删了、下次会拉下来的

每组都有计数，点开是文件列表，每行显示状态标签（`M` 修改 / `A` 新增 / `D` 删除）+ 文件路径。

最妙的是它会**自动刷新**：你在编辑器里改了、新建了、删除了、重命名了任何文件，面板 1.5 秒后自动重新计算（去抖处理，不会狂刷接口）。你不用手动去点「刷新」，盯着它就行。

## 三、核心二：差异对比视图（DiffView）

光列出文件名还不够。点文件列表里的「查看」图标，会打开一个行级差异对比视图。这一块是这次改动量最大的部分（新建 867 行），功能也最细：

- **布局切换**：可以在「单栏内联 diff」和「双文件完整视图」之间切换，像 GitHub 单栏 / 双栏那样各取所需。
- **收起未更改片段**：文件很长但只改了几行时，自动把中间没动的部分折叠成省略号，一眼定位改动。
- **同步滚动**：开了之后两边对照滚动，默认就是开的。
- **差异块一键还原**：每个被改动的区块旁边有个还原按钮，点一下就把那一块恢复到「上次成功同步时的版本」。新增的文件还原即删除，删除的文件还原即找回，修改的文件还原即回退。比 `git checkout -- <file>` 还细——它是**按块（hunk）回退，不是整文件**。

支持五种 diff 场景：`本地新增 / 本地删除 / 本地修改 / 远端修改 / 远端删除`，每种都有对应的配色和还原逻辑。

## 四、核心三：暂存区与选择性提交

这是从「全量推送」进化到「版本控制」的关键一步。

文件列表每一行右侧有 `+` / `-` 图标：

- 点 `+` → 把文件**暂存**（放进 Staged 组）
- 点 `-` → **取消暂存**
- 组标题上还有「全部暂存 / 全部取消 / 全部放弃」的快捷按钮

提交时，**只推送你暂存的文件**。如果你一个都没暂存就点提交，面板会提示「没有可提交的文件」，不会稀里糊涂把乱改的一起推上去。

配合上一节的 DiffView，工作流就变成了 Git 用户最熟悉的那套：

> 看状态 → 看 diff → 挑几个文件暂存 → 写一句提交信息 → 提交。

而且「放弃更改」也做成了带确认弹窗的危险操作：把本地文件恢复到上次同步的远端版本，避免手滑。

## 五、顺手做的体验优化

功能是大头，但几个小修小补也顺手做了：

- **侧边栏按钮可配置隐藏。** 原来固定在侧边栏的「同步图标」和「Git 面板图标」，现在在设置里能单独开关。嫌挤的用户可以只留一个。
- **设置面板重新分组。** 把零散的设置项按「账户 / 同步 / 排除 / 界面」归类，找东西不用再从头扫到尾。
- **提交按钮修了两个 bug**：之前写好的 commit message 偶尔不生效、提交后面板不刷新——这轮一并修了（提交后会在释放 busy 标志之后再刷新，避免列表视觉上没清空）。

## 六、1.0.2：移动端兼容与合规修复

功能做完，发版前做了一轮合规审计，修的全是「桌面端没事、移动端会崩」的坑：

**1. SHA-1 改成纯 JS 实现。** 原来算文件哈希用的是浏览器的 `crypto.subtle.digest`。在 Obsidian 移动端的 webview 里，非安全上下文下 `crypto.subtle` 可能是 `undefined`——同步一算哈希就崩。插件是 `isDesktopOnly: false`（必须保证移动端可用），所以新增了一个自包含的纯 JS `sha1()`，严格按 Git blob 格式（`blob <size>\0<content>`）计算，并用 `git hash-object` 端到端校验过：空文件、含中文 emoji、1MB 大文件，结果和 Git 完全一致。

**2. DiffView 不再依赖未公开 API。** 之前靠 `app.plugins.getPlugin()` 拿插件实例，这是个不稳定接口。改成 `main.ts` 在 `onload()` 里用 `setDiffPluginInstance()` 主动注入单例，并保留了回退路径，更稳。

**3. 设置面板类型收敛。** 分支下拉框的组件类型、`selectEl` 清空方式都改成 Obsidian 官方推荐写法（`empty()` 替代直接改 `innerHTML`），少踩坑。

**4. 版本映射对齐。** `versions.json` 补齐了 `1.0.1` / `1.0.2` 的映射（都指向 `minAppVersion 1.8.7`），保证 BRAT 和社区市场能正确路由到对应版本；`README` 里「排除目录」的说明也从错误的「逗号分隔前缀」更正为「直接编辑 `.gitignore` 原始规则」。

**5. CI 自动构建。** 仓库里加了 GitHub Actions 的 release 工作流：打一个 tag 并推送 → 自动 `npm install` + 构建出 `main.js` → 自动发 Release。以后发版只需要打 tag，不用在本地手工构建。

## 🚀 如何更新

**已经在用 1.0.0 / 1.0.1 的用户：**

- 通过 BRAT 或社区市场更新即可，无需重装。
- 更新后建议去设置里看看侧边栏按钮开关、分组是否符合习惯。
- 移动端用户这次是必更——1.0.1 及之前在手机上同步可能因哈希崩溃。

**新用户：**

1. Obsidian → 设置 → 第三方插件 → 关闭安全模式
2. 浏览，搜索 **Gitee Sync Plus**，安装启用
3. 配置 Gitee / GitHub 的 Token、用户名、仓库名、分支
4. 左侧打开 Git 面板，体验一眼看全改动 + 选择性提交

## 常见问题

**Q：暂存区和 Git 的暂存区是一回事吗？**

A：概念一样——都是「标记哪些改动要进入下一次提交」。但插件底层没有本地 git 程序，它是基于自己的三方同步模型（本地 / 远端 / 上次同步基线）实现的，对 Obsidian 用户完全透明，不需要懂 Git。

**Q：放弃更改会丢文件吗？**

A：放弃的是「本地未同步的改动」，文件会恢复到上次成功同步时的远端版本。操作前有确认弹窗，不会静默执行。

**Q：手机上能用 Git 面板吗？**

A：能。1.0.2 专门修了移动端哈希崩溃的问题，iOS / Android 均可用，界面和桌面端一致。

**Q：会和 Obsidian 自带的 Git 插件冲突吗？**

A：不会互相依赖，但建议别让两个工具同时管理同一个仓库，避免状态打架。

## 📋 写在最后

这轮更新的本质，是把 Gitee Sync Plus 从「同步工具」往「版本控制面板」推了一步。

我始终觉得，同步不该是一个黑盒——你有权在改动被推上去之前，看清它是什么、决定哪些要、哪些不要。Git 用几十年证明了这套心智模型是对的，那 Obsidian 里也该有。

1.0.0 解决了「能不能同步隐藏文件」，1.0.2 解决了「同步得清不清楚、可控不可控」。下一步想做的是冲突时的可视化合并……如果你也想要，评论区扣个 1。
