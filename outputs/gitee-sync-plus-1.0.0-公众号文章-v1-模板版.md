# 🔔 开篇导语

如果你是 Obsidian 重度用户，想必对「多设备同步笔记」这件事又爱又恨。官方的 Obsidian Sync 好用但不便宜，iCloud / OneDrive 在 Windows 和 Android 之间经常抽风，Git 方案虽然免费但手动 git add / commit / push 实在反人类。

Gitee Sync Plus 就是一个解决这个痛点的 Obsidian 插件——它在你编辑笔记的同时，自动以文件粒度把 vault 同步到 Gitee 或 GitHub 仓库，零手动操作。最近插件做了一轮大刀阔斧的重构，发布了 **1.0.0 正式版**，核心能力从「能用」进化到了「好用」。

如果你也用过 Git 同步方案但被各种小问题劝退过，不妨认真看完这篇文章，或许能给你一个全新的解决思路。

# 这次 1.0.0 更新了什么

这次更新跨度很大，从原本的 0.2.4 直接跳到 1.0.0，共修改了 13 个文件、新增 523 行代码、删除 125 行。改动的三个核心方向是：**同步引擎重构**、**设置界面改版**、**插件品牌升级**。

## 一、同步引擎：用 .gitignore 替换硬编码过滤

**这是本轮改动最大的部分。**

老版本的插件通过硬编码前缀列表来排除文件——所有 `.obsidian/`、`.git/` 开头的隐藏目录一律跳过，用户没法自己控制。更尴尬的是，`.obsidian` 下的用户自定义配置（比如快捷键、主题设置、插件配置）完全不能同步，换台设备就得重新设一遍。

新版本干了两件事：

- **引入标准 `.gitignore` 规则**：新增了一个 154 行的 `src/gitignore.ts` 模块，底层用 `ignore` npm 包做规则匹配，和你平时写 `.gitignore` 的语法完全一致。
- **自动管理排除规则**：插件在 vault 根目录维护一个 `.gitignore` 文件，默认排除 `.git`、回收站（`.trash`）、工作区状态文件等。插件管理的规则标记在 `# >>> gitee-sync-plus managed exclusions >>>` 和 `# <<< gitee-sync-plus managed exclusions <<<` 之间，你手动添加的其他规则完全不受影响。

> 💡 **这意味着什么？** 你可以在 `.gitignore` 里自由添加 `private/`、`draft/`、`*.tmp` 等自定义规则；同时 `.obsidian` 下的配置也能正常同步了，换设备的体验大幅提升。

更底层的变化是，文件操作全面改用 `vault.adapter` 而不是 `vault.getFiles()`——前者能读到隐藏文件，后者只能拿到 Obsidian 索引范围内的文件。读文件、写文件、删文件、建目录全部绕过 Obsidian 索引限制，保证隐藏目录和文件能被完整同步。

## 二、设置界面：分支下拉框 + 统一布局

老版本的分支字段是个纯文本输入框——你得手动敲 `main` 或 `master`，拼错了就同步失败。

新版本改成了**动态下拉框**：填好用户名、仓库名和 Token 之后，点一下刷新按钮，插件就自动从 Gitee / GitHub 的 API 拉取仓库所有分支，下拉选择就行了。

为了不频繁调 API，下拉框数据有 5 分钟内存缓存——打开设置页不自动请求，只有你点刷新才拉新数据；5 分钟内再次打开直接用缓存。

另外，Gitee 和 GitHub 两种平台的设置项顺序也统一成了：**Token → 用户名 → 仓库名 → 分支**，再也不会出现两个平台配置项位置不一致的困惑。

## 三、品牌升级：Gitee Sync → Gitee Sync Plus

社区插件市场里有同名的 `gitee-sync` 插件，为了避免混淆，插件正式改名为 **Gitee Sync Plus**，ID 从 `gitee-sync` 改为 `gitee-sync-plus`。

改名范围覆盖了 10 个文件——`manifest.json`、`package.json`、`README.md`、脚本、源码里的日志前缀、本地存储 key 等全部替换。

> ⚠️ **注意**：这是一次 breaking change。老用户的插件目录从 `.obsidian/plugins/gitee-sync/` 变成 `.obsidian/plugins/gitee-sync-plus/`，之前的设置和同步基线不会自动迁移，需要**重新配置 Token 和仓库信息**。

另外版本号也从 0.2.4 重置为 1.0.0，`versions.json` 清空历史记录只保留当前版本，标志着这个项目作为一个全新独立插件的起点。

# 🚀 如何升级 / 安装

## 新用户安装

1. 打开 Obsidian → 设置 → 第三方插件 → 关闭安全模式
2. 点击「浏览」，搜索 **Gitee Sync Plus**
3. 安装并启用
4. 在插件设置中配置 Gitee 或 GitHub 的 Token、用户名、仓库、分支

## 老用户升级（从 gitee-sync 迁移）

1. 在 Obsidian 中卸载旧版 `Gitee Sync` 插件
2. 安装新版 `Gitee Sync Plus`
3. **重新配置 Token 和仓库信息**（设置数据不会自动迁移）
4. 插件首次启动会自动在 vault 根目录生成 `.gitignore`，旧的 `excludeFolders` 设置也会自动迁移进去
5. 进行一次手动同步，检查是否正常

## 四、常见问题 / 避坑指南

**Q：.gitignore 里的插件管理规则和我手写的规则冲突了怎么办？**

A：不会冲突。插件管理的规则在独立的注释块里（`>>> gitee-sync-plus managed exclusions >>>` 到 `<<< gitee-sync-plus managed exclusions <<<`），你手动写的规则在块外面，互不影响。下次更新插件版本时，只有块内规则会变化。

**Q：升级后同步状态消失了怎么办？**

A：这是预期行为。本地同步状态 key 从 `gitee-sync-sync-state-v1` 变成了 `gitee-sync-plus-sync-state-v1`，旧的状态数据不兼容。执行一次完整同步即可重建基线。

**Q：隐藏文件（如 `.obsidian/` 下的配置）现在能同步了吗？**

A：能。只要你的 `.gitignore` 没有排除它们，插件就会完整同步。默认的插件管理规则只排除了 `.obsidian/workspace.json` 和 `.obsidian/workspace-mobile.json`（这两个是工作区状态，不同设备不应该同步），其余 `.obsidian` 下的配置都在同步范围内。

**Q：GitHub 也能用吗？**

A：能用。Gitee 和 GitHub 两个平台后端都完整支持，在设置页切换「平台」下拉框即可。

# 📋 全文总结

Gitee Sync Plus 1.0.0 是一次「脱胎换骨」式的更新，核心思路是把控制权还给用户：

- **同步粒度更灵活**：`.gitignore` 替代硬编码，想排除什么你说了算
- **隐藏文件也能同步**：换设备不再需要重新配快捷键和主题
- **操作体验更友好**：分支下拉框、统一设置布局、一键刷新
- **品牌独立清晰**：新名字、新 ID，和社区市场其他插件不再混淆

如果你一直在找一款免费、可控、和 Git 工作流天然契合的 Obsidian 同步方案，不妨试试 Gitee Sync Plus。
